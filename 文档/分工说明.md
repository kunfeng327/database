# 小组分工说明（5 人 × 5 条业务线）

> 选题：社区居家养老智慧服务平台 · 数据库系统课程设计
> 原则：**一人一条业务线，端到端负责**（数据字典 → 局部 E-R → DDL/种子 → 视图/触发器 → 多表 SQL → 持久层 DAO+测试 → 报告对应章节）；公共事务（全局整合、安全、PPT、答辩）做二次分配保证工作量平衡。
> 分支规范：每人在自己的 `feature/<名字拼音>-<业务线>` 分支开发，PR 互审后合入 main（详见 README 协作流程）。

## 二、每条线的具体任务清单（对照现有 demo 的差距）

### 线1 老人档案与能力评估（A）
已有：3 张表、视图 v_elder_assessment_plan、评估过期→暂停计划存储过程、复评恢复逻辑。
待做：① 数据字典（全字段类型/约束/取值范围）；② 局部 E-R 图（PowerDesigner/Visio）；③ 再设计 2 个视图（如"独居老人未评估清单""各社区能力等级分布"）；④ 档案/评估的 DAO 单元测试（含事务回滚用例）。

### 线2 服务下单与派单（B）
已有：3 张表、订单状态机、3 个触发器（容量/资质校验、booked 自动维护、完成回写）、推荐护工查询。
待做：① 字典+局部 E-R；② 补 2 个视图（如"改派历史追溯视图""各渠道订单构成视图"）；③ DAO 层抽离与 pytest 测试（当前逻辑在 app.py 路由里，要迁移为独立持久层模块——这是任务书 3.3 的硬要求）。

### 线3 护工与排班（C）
已有：2 张表、排班唯一约束与容量 CHECK、v_schedule_capacity。
待做：① **新建 work_hour 工时表**（护工/派单/签到/签退/签到位置/围栏校验/有效工时）；② 证书到期前 30 天预警视图、"跨区接单检查"视图；③ 签到签退触发器（工时自动计算）；④ 全部复杂 SQL 的执行计划分析（EXPLAIN）与索引优化前后对比。

### 线4 健康监测与应急响应（D，全新模块）
从零做：① device（设备类型/绑定老人/解绑保留历史）、vital_sign（指标类型/阈值/异常标记，数据量大讨论分区）、emergency（事件等级/响应时限/处置闭环）三表；②"超时未响应自动升级"触发器（对应任务书示例）、体征异常自动标记触发器；③ 视图 3 个（当日异常体征、待响应事件、设备绑定状态）；④ DAO+测试。

### 线5 补贴核算与质量监管（E）
已有：2 张表、防重复申报唯一约束、审核状态流转、v_claim_progress。
待做：① **新建 quality_inspection 质量抽查表**（订单/护工、抽查方式、评分、问题标签、整改闭环）；② 整改未完成限制接单的触发器；③ 视图补 2 个（抽查结果与护工评分联动、各区县补贴发放统计）；④ 报告/PPT 模板套写（模板文件在仓库根目录）。
