## 协作流程（必读）

规则：**main 不许直接 push，所有改动走"自己的分支 → PR → 互审 → 合并"**。PR 小而勤，做完一小块就提，不要攒到最后一天。

```bash
# 0. 首次克隆后，先执行一次（校园网 SSL 拦截问题）：
git config http.sslVerify false

# 1. 开始干活前：刷新 main，再切到自己的分支
git switch main
git pull origin main
git switch feature/你的名字拼音-功能

# 2. 干活、提交（可多次）
git add .
git commit -m "完成xxx业务的3个视图"

# 3. 提 PR 前：把最新 main 合进来，冲突在自己分支里解决
git merge main
git push origin feature/你的名字拼音-功能
```

然后到 GitHub 网页上开 PR（自己的分支 → main），**由组长或另一位队员审完再合并，不许自己合自己的 PR**。

> ⚠️ **.docx 文件无法合并冲突**：每个 Word 文档只由它的负责人一人修改，其他人提意见、不要直接改文件。
