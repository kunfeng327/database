## 演示系统（前后端 Demo）

技术栈：**MySQL 9.x + Flask + PyMySQL + 原生 HTML/CSS/JS**（无外部 CDN 依赖，离线可跑；界面设计参考 [gentelella](https://github.com/ColorlibHQ/gentelella)，MIT 协议）。

已实现任务书 3.4 的安全机制：**密码加盐哈希（SHA256(盐+密码)）、连续失败 5 次锁定 10 分钟、会话 30 分钟超时、RBAC 角色权限控制**（接口级校验 + 数据行级过滤：家属只见自家老人订单，护工只见派给自己的单）。

### 运行方式

- **一键**：双击 `启动演示.bat`，输入 MySQL root 密码即可（可选是否重置演示数据）。
- **手动**：
  ```bash
  # 1. 导入数据库（按序执行 4 个脚本）
  mysql -h127.0.0.1 -uroot -p --default-character-set=utf8mb4 < sql/01_schema.sql
  #    …… 02_seed / 03_views / 04_procs_triggers 同理
  # 2. 配置密码：复制 src/backend/config_example.py 为 config_local.py（已被 .gitignore 排除）
  # 3. 启动
  cd src/backend && pip install flask pymysql && python app.py
  ```
  打开 http://127.0.0.1:5000

### 答辩演示走查顺序（约 5-8 分钟）

1. **登录与 RBAC**：用家属账号登录只见自家数据；故意点派单提示"无权限"；换护工/监管账号各看一眼界面差异；
2. **评估闭环**：家属端看评估记录与到期提醒；社区端"运维"执行存储过程暂停过期计划 → 给老人录复评 → 暂停的照护计划自动恢复；
3. **总览**（社区管理员）：超时未派单、待暂停计划等指标来自视图；
4. **下单被拒**：给"高崇礼"下单 → 提示能力评估已过期（应用层校验）；
5. **派单被拒**：给订单推荐护工后，选证书已过期的"周德海" → 数据库触发器 SIGNAL 拒绝；
6. **正常闭环**：下单 → 推荐护工 → 派单（排班 booked 由触发器自动 +1）→ 护工账号登录完成服务（订单状态由触发器回写"已完成"）；
7. **改派**：保留原派单记录与原因，订单回到待派单；
8. **补贴**：社区端申报（自动汇总账期内已完成订单、防重复申报）→ 监管账号登录完成审核流转。

## 协作流程（必读）

规则：**main 不许直接 push，所有改动走"自己的分支 → PR → 互审 → 合并"**。PR 小而勤，做完一小块就提，不要攒到最后一天。

```bash
# 0. 首次克隆后，先执行一次（校园网 SSL 拦截问题）：
git config http.sslVerify false

# 1. 开始干活前：刷新 main，再切到自己的分支
git switch main
git pull origin main
git switch feature/你的名字拼音-功能

# 2. 干活、提交（可多次）
git add .
git commit -m "完成xxx业务的3个视图"

# 3. 提 PR 前：把最新 main 合进来，冲突在自己分支里解决
git merge main
git push origin feature/你的名字拼音-功能
```

然后到 GitHub 网页上开 PR（自己的分支 → main），**由组长或另一位队员审完再合并，不许自己合自己的 PR**。

> ⚠️ **.docx 文件无法合并冲突**：每个 Word 文档只由它的负责人一人修改，其他人提意见、不要直接改文件。
